---
name: spec-review
description: Plan a bounded change with OpenSpec or run a Ponytail-style read-only repository review using GitHub issue and PR traceability.
---

Read `.github/spec-and-review.md` and the repository's existing instructions first. For a spec, reuse the owning GitHub issue, define testable scenarios, and record strict validation and the draft PR. For an audit, pin the revision, map the important flows, and report evidence and coverage gaps without changing code. Favor the smallest complete fix without weakening validation, accessibility, or tests. Link existing work rather than duplicating it. Do not send private source externally or operate production without separate authorization.
